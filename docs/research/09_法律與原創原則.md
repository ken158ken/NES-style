# 09 法律與原創原則

> **免責聲明**：本文件是研究整理，**不是法律意見**。各國法律不同（台灣著作權法、美國 DMCA / Copyright Act、日本著作権法），
> 實際遇到爭議請諮詢律師。本文件的目的是把「已知的公開事實」與「社群通行慣例」整理成**可執行的自我檢查表**，
> 讓本專案從第一行程式碼開始就走在安全側。

## 摘要（10 行內）
1. 任天堂官方立場：對其智慧財產的**所有使用都需要授權**，並以 DMCA 下架、警告信、訴訟三種手段執行。[源]
2. 官方 FAQ 明文反對的是**未授權遊戲重製（ROM）、規避裝置、仿冒品**；FAQ 本身**未直接談同人遊戲**，但實務上曾一次對 Game Jolt 下架 **379 款**同人作。[源]
3. 法律上「自製相容遊戲」本身合法：只要沒有直接抄程式碼、沒侵犯專利 / 商標，也**不得暗示獲得任天堂背書**。[源]
4. GB / GBC 開機 ROM 會檢查卡帶內的**任天堂 logo 點陣資料**，而該 logo 是註冊商標——這是 homebrew 最出名的灰色地帶。[源]
5. 判例：*Sega v. Accolade*（9th Cir. 1992）認定為取得介面規格而做的「中介重製」（反組譯）屬**合理使用**。[源]
6. 判例：*Atari Games v. Nintendo*（Fed. Cir. 1992）認定「未受污染的反向工程是合理使用」，但 Atari 因以欺騙手段取得原始碼而敗訴。[源]
7. 對本專案的結論：**走 100% 原創 IP**（原創角色、原創曲、原創關卡、原創程式碼），所有風險幾乎歸零。[推論]
8. 素材授權安全清單：**CC0**（如 Kenney，完全免歸屬）、**OFL 1.1**（字型可內嵌於 app，需注意 Reserved Font Name）。[源]
9. 危險區：角色名 / 造型 / 招式名 / 旋律 / UI 版面 / 標題字體，**六項都要逐一對照檢查**。[推論]
10. Homebrew 發佈慣例：原創 IP + 開源授權（MIT / zlib / GPL / CC-BY-SA）+ 明確的「非官方、無關聯」聲明。[推論]

## 1. 為什麼要先談法律

本專案的 README 已經寫明：

> 「未來開發的美術、音樂、關卡一律原創，不使用任何版權 ROM / 圖片 / 音訊。」[源]（本專案 README.md）

隔壁 `../卡比之星` 的 SPEC 也寫明：

> 「所有美術、音樂、關卡皆為本專案原創（以程式碼手繪像素圖、以 Web Audio 合成原創曲）。
> 嚴禁使用任何任天堂 / HAL 的 ROM、音樂、擷取圖片。技術棧僅用 MIT / 無授權的瀏覽器內建 API。」[源]

但 `../卡比之星` 的**名稱、角色名（卡比、瓦豆魯迪、迪迪迪大王、魅塔騎士）、能力名、世界名**仍直接沿用任天堂 / HAL 的 IP。
因此它屬於「同人」而非「原創」，本文件第 4 節會說明其風險等級。**本專案（紅白機遊戲開發）應走完全原創路線。**[推論]

## 3. 相關判例

### 3.1 Sega Enterprises Ltd. v. Accolade, Inc.（977 F.2d 1510, 9th Cir. 1992）
| 要點 | 內容 | 標註 |
|---|---|---|
| 事實 | Accolade 反組譯 Sega Genesis 軟體以了解其安全機制，之後發行未授權遊戲 | [源] |
| 判決 | 法院認定 Accolade 的反向工程與後續發行**受合理使用保護** | [源] |
| 理由 | 「中介重製」（僅為發現功能性介面規格而複製，之後獨立實作）屬合理使用；反組譯是取得 Sega 程式中「概念與功能要素」的唯一途徑，且 Accolade 有正當理由 | [源] |
| 商標部分 | Sega 因利用其安全系統把自家商標印在 Accolade 的遊戲上而被判有責 | [源] |

### 3.2 Atari Games Corp. v. Nintendo of America Inc.（Fed. Cir. 1992）
| 要點 | 內容 | 標註 |
|---|---|---|
| 事實 | 任天堂以 **10NES** 鎖碼阻止未授權卡帶在 NES 上執行；Atari 試圖破解 | [源] |
| 判決核心句 | 「未受（竊得副本）污染、且為理解 10NES 所必要的反向工程，屬合理使用」 | [源] |
| 為何 Atari 敗訴 | Atari 以**欺騙手段**取得任天堂原始碼（從著作權局調閱），因而喪失合理使用抗辯 | [源] |
| 學者結論 | 兩案的主要差別就是「Atari 說謊取得程式碼」 | [源] |

### 3.3 這兩案對 homebrew 的含意
| 含意 | 說明 | 標註 |
|---|---|---|
| 做「相容卡帶 / ROM」本身合法 | 競爭者在未直接抄襲、未侵害專利 / 商標的前提下，可合法製造相容產品 | [源] |
| 但不得暗示背書 | 「不能讓人以為你獲得任天堂認可，那是商標問題」 | [源] |
| 標頭 / logo 的灰色 | GB 開機 ROM 讀 logo 兩次（一次顯示、一次驗證卡帶內是否有原版 logo）；「Nintendo®」是註冊商標，未授權使用容易成為訴訟標的 | [源] |
| 標頭是必要的 | homebrew 應提供有效的標頭；任天堂當年要求開發者附上描述卡帶硬體的標頭，模擬器與快閃卡也靠它判斷如何模擬 | [源] |

> **實務判斷**：`.gb` ROM 檔要能在真機 / 模擬器啟動，技術上必須含那 48 bytes 的 logo 資料。
> 社群做法是照做（全部 GB homebrew 都這樣），但要清楚這仍是灰色地帶，且**絕對不要**額外把 Nintendo 商標放進遊戲畫面、標題、宣傳素材。[推論]（logo 檢查 [源]、商標風險 [源]）

## 4. 同人 / 致敬的風險分級

| 等級 | 定義 | 例子 | 風險 | 建議 |
|---|---|---|---|---|
| **R0 完全原創** | 原創角色、世界、名稱、音樂、程式碼；只保留「類型」與「時代風格」 | 原創的 8-bit 橫捲平台遊戲，角色是自創生物 | 幾乎為零 | ✅ **本專案採用** |
| **R1 機制致敬** | 沿用玩法機制但一切命名 / 造型原創 | 「吸入敵人取得能力」的原創角色遊戲 | 極低（玩法機制一般不受著作權保護，只有表達受保護） | ✅ 可採用，但避免招式名一字不差 [推論] |
| **R2 視覺風格致敬** | 模仿某遊戲的美術方向（色調、構圖、UI 佈局）但無角色重用 | 「像《惡魔城》那樣的哥德城堡 + 血條 UI」 | 低～中；UI 版面若一模一樣會踩到 trade dress | ⚠️ 要有明顯差異化 [推論] |
| **R3 同人（沿用角色名 / 造型）** | 使用他人角色、名稱、世界觀，自製程式與素材 | `../卡比之星`（卡比、迪迪迪、瓦豆魯迪等） | **中～高**；任天堂已對此類作品大規模下架 | ⚠️ 僅限**本機私用、不公開發佈、不營利** [推論]（下架事實 [源]） |
| **R4 同人 + 公開散佈** | R3 且放上 itch.io / GitHub / Game Jolt | — | **高** | ❌ 不建議 [推論] |
| **R5 使用原作素材** | 直接使用擷取的圖、原曲 MP3 / MIDI、拆包的 ROM 資料 | — | **很高**（直接重製，無合理使用空間） | ❌ 絕對禁止 [推論] |
| **R6 商業化** | 任一等級加上販售 / 廣告收益 | Game Jolt 案理由提及廣告獲利 | **最高** | ❌ 絕對禁止 [推論]（獲利為加重因素 [源]） |

### 4.1 `../卡比之星` 的定位與建議
| 項目 | 現況 | 標註 |
|---|---|---|
| 素材 | 100% 原創（程式手繪像素 + Web Audio 合成），無任何擷取資產 | [源]（該專案 SPEC.md） |
| 名稱 / 角色 | 沿用任天堂 / HAL 的角色名與造型 → **R3** | [推論] |
| 建議 | 保持**本機 / 私人使用**，不要公開發佈、不要放廣告、不要販售；若未來想公開，**做一次「換皮」**：角色改名改造型、能力名重寫、世界名重寫，即可降到 R1 | [推論] |
| 好消息 | 由於素材本來就全原創，換皮**只需改名字與像素圖，程式碼完全不用動** | [推論] |

## 5. 各要素的界線

### 5.1 程式碼 / ROM
| 行為 | 判斷 | 標註 |
|---|---|---|
| 自己寫的 6502 / C / JS 程式碼 | ✅ 安全，著作權歸你 | [推論] |
| 使用 cc65 / GBDK / Butano / libtonc | ✅ 安全（各有開源授權，Butano 為 zlib） | [源]（Butano zlib [源]） |
| 反組譯商業 ROM 來「學習手法」 | ⚠️ 灰；Sega/Atari 兩案認可「為介面相容所必要」的中介重製，但「學習關卡設計」不在此列 | [推論]（判例 [源]） |
| 把反組譯出的程式碼貼進自己遊戲 | ❌ 直接侵權 | [推論] |
| 散佈商業 ROM | ❌ 明確違法（任天堂明文） | [源] |
| 自製 ROM 內含任天堂 logo 點陣（GB 開機必需） | ⚠️ 灰色但為社群通行做法 | [推論]（logo 為商標 [源]） |
| 使用 iNES 標頭 | ✅ 標頭是必要且社群規範 | [源] |

### 5.2 美術 / 素材
| 行為 | 判斷 | 標註 |
|---|---|---|
| 從 ROM 擷取精靈圖 / 背景 | ❌ 直接重製 | [推論] |
| 從 spriters-resource 之類網站抓圖 | ❌ 那些圖仍是原公司的著作 | [推論] |
| 「照著參考重畫」但造型可辨識為原角色 | ❌ 衍生作品 | [推論] |
| 自創角色但保留「粉紅圓球 + 紅腳」這種高辨識特徵 | ⚠️ 可能構成實質近似 | [推論] |
| 完全自創造型（不同體型、配色、剪影） | ✅ | [推論] |
| **剪影測試** | 把角色縮成 32×32 純黑剪影，若旁人能一眼說出是哪個 IP → 重畫 | [推論] |
| 使用 CC0 素材（Kenney 等） | ✅ 公眾領域，商用亦可，**不需歸屬** | [源] |
| 使用 CC-BY 素材 | ✅ 但**必須署名** | [推論] |
| 使用 CC-BY-SA 素材 | ⚠️ 你的作品可能被要求同樣授權 | [推論] |
| 使用 CC-BY-NC 素材 | ⚠️ 不得商用 | [推論] |

### 5.3 音樂 / 音效
| 行為 | 判斷 | 標註 |
|---|---|---|
| 使用原作 MP3 / OGG / 錄音 | ❌ 錄音著作 + 音樂著作雙重侵權 | [推論] |
| 使用原作 MIDI / NSF / GBS | ❌ 那是曲子本身（音樂著作） | [推論] |
| 自己用 chiptune 工具**重製原曲** | ❌ 改編權；即使自己演奏 / 打譜也是衍生作品 | [推論] |
| 原創曲但**主旋律動機與原曲高度相似** | ⚠️ 可能構成抄襲 | [推論] |
| 原創曲，僅使用相同**音色 / 編制 / 曲風**（方波 + 三角 + 雜訊、快節奏 8-bit） | ✅ 風格不受著作權保護 | [推論] |
| **旋律相似度自檢** | 連續 **4 小節以上的音高＋節奏輪廓**與已知名曲吻合 → 改寫。可用哼唱搜尋（Google Hum to Search）或人工聽測 | [推論] |
| 使用 hUGEDriver | ✅ 明確標示 public domain | [源] |
| 使用 FamiStudio Sound Engine | ✅ 開源（授權見其 repo） | [推論] |

### 5.4 名稱 / 文字
| 要素 | 風險 | 標註 |
|---|---|---|
| 角色名（Kirby、Mario、Link…） | ❌ 商標 + 著作權雙重 | [源]（商標清單 [源]） |
| 主機名 / 商標（Nintendo、Game Boy、Famicom、NES） | ❌ 不可用於標題、logo、宣傳詞 | [源] |
| 描述性使用（「本遊戲可在 Game Boy 模擬器執行」） | ⚠️ 一般認為屬指示性合理使用，但仍要避免放在標題 / 圖示 | [推論] |
| 招式名 / 道具名（一字不差照搬） | ⚠️ 單詞通常不受著作權保護，但整組照搬會被視為重製表達 | [推論] |
| 關卡名 / 世界名照搬 | ⚠️ 同上 | [推論] |
| 「不隸屬於任天堂」聲明 | ✅ 應加；但**不能**把它當侵權的免死金牌 | [推論] |

### 5.5 UI / 版面（trade dress）
| 要素 | 風險 | 標註 |
|---|---|---|
| 血條、能力圖示的**位置與形狀**一模一樣 | ⚠️ 可能構成 trade dress 混淆 | [推論] |
| 標題畫面的排版、字體風格、logo 形狀 | ⚠️ logo 是最危險的單一元素 | [推論] |
| 通用 UI 慣例（左上生命、右上分數、下方血條） | ✅ 業界慣例不受保護 | [推論] |
| 過關結算畫面的資訊種類（時間 / 分數 / 收集） | ✅ 功能性 | [推論] |

## 6. Homebrew 合法發佈慣例

| 慣例 | 內容 | 標註 |
|---|---|---|
| **原創 IP** | 角色、名稱、世界觀全部自創；這是絕大多數 NESdev / gbadev 商業 homebrew（如各種 itch.io / 實體卡帶作品）的做法 | [推論] |
| **開源授權** | 程式碼常用 MIT / zlib / GPL；音樂驅動 hUGEDriver 為 public domain、Butano 為 zlib、Mesen 為 GPLv3 | [源] |
| **素材授權分離** | repo 內 `LICENSE`（程式碼）與 `ASSETS-LICENSE`（美術 / 音樂，常用 CC-BY-SA 或 CC0）分開寫 | [推論] |
| **不附商業 ROM** | repo 內只放自製 ROM 或建置腳本，絕不含任何商業遊戲檔 | [推論] |
| **不附 BIOS / 開機 ROM** | GB / GBA 的開機 ROM 是任天堂著作，不可散佈（模擬器多半不需要它也能跑） | [推論] |
| **免責聲明** | README / 標題畫面附「本作為非官方作品，與任天堂株式會社無任何關聯」 | [推論] |
