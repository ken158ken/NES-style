# 07 掌機規格與差異：Game Boy / Game Boy Color / Game Boy Advance

## 摘要（10 行內）
1. **GB（1989）**：Sharp SM83 @ 4.194304 MHz、160×144、4 階灰（綠），8 KB WRAM + 8 KB VRAM，APU 4 聲道（2 脈衝 + 波表 + 雜訊）。[源]
2. **GBC（1998）**：同核心可切 8.388608 MHz 倍速，VRAM 16 KB / WRAM 32 KB（分頁），32768 色中同畫面約 56 色。[源]
3. **GBA（2001）**：ARM7TDMI @ 16.78 MHz、240×160、15 位元色（32768 色），96 KB VRAM + 256 KB EWRAM + 32 KB IWRAM。[源]
4. 三台都是 **8×8 磁磚 + 精靈**架構，與 NES 同血統；差別在「調色盤數量、每磁磚色深、精靈上限、有無縮放旋轉」。[源]
5. GB 精靈 40 個 / 每掃描線 10 個；NES 是 64 個 / 每掃描線 8 個；GBA 是 128 個（OAM 1 KB）。[源]
6. GB / GBC 的色彩限制比 NES **寬鬆**（GBC 每磁磚 4 色、8 組背景調色盤可自由選 32768 色），但**解析度更小**（160×144 對 256×240）。[源]
7. GBA 在磁磚模式下可同時 511 色、Bitmap 模式可全 32768 色，另有仿射（縮放 / 旋轉）背景與精靈、Alpha 混色、馬賽克、視窗。[源]
8. 音源：GB / GBC 4 聲道 PSG；GBA 保留那 4 聲道再加 **2 條 8-bit PCM DMA 聲道**（Direct Sound），所以能播真取樣。[源]
9. 存檔：GB / GBC 用電池 SRAM（MBC）；GBA 有 SRAM / Flash / EEPROM 三種。NES 則是 mapper + 電池 SRAM 或密碼。[源]
10. 設計上的關鍵差異：**螢幕小 → 放大角色、縮小視野、UI 要極簡**；**按鍵少（GB 只有 A/B）**；**多人靠連線纜**；**電池續航 → 適合短關卡 / 隨時存檔**。[推論]

## 1. 為什麼要研究掌機

本專案主軸是 NES / Famicom 像素風，但掌機三兄弟與 NES 共用同一套「磁磚 + 精靈 + 調色盤」心智模型，
研究它們的價值在於：

| 目的 | 說明 |
|---|---|
| 找出「像素風」的可行規格帶 | NES 256×240 / GB 160×144 / GBA 240×160 是三種截然不同的構圖尺度 [源] |
| 選擇技術路線 | GB / GBC ROM 的開發門檻明顯低於 NES（有 C 編譯器 GBDK、無程式碼工具 GB Studio） [源] |
| 借用限制當風格 | GB 的 4 階灰、GBC 的每磁磚 4 色，都是現成而且好看的「自我約束」 [推論] |
| 音樂設計 | GB 的波表聲道（32 個 4-bit 取樣）能做出 NES 三角波做不到的音色 [源] |

## 2. Game Boy（DMG，1989）

### 2.1 基本資料
| 項目 | 數值 | 標註 |
|---|---|---|
| 發售日 | 日本 1989-04-21 / 北美 1989-07-31 / 歐洲 1990-09-28 | [源] |
| CPU | Sharp SM83（Intel 8080 與 Zilog Z80 的混血），4.194304 MHz | [源] |
| 資料匯流排 | 8-bit 資料 / 16-bit 位址（64 KB 位址空間） | [源] |
| 螢幕 | 2.5 吋反射式 LCD，160×144，10:9 | [源] |
| 色彩 | 4 階灰（實機呈綠色調） | [源] |
| 更新率 | ~59.7 Hz | [源] |
| WRAM | 8 KB | [源] |
| VRAM | 8 KB | [源] |
| HRAM | 127 bytes（高速零等待暫存區，DMA 期間唯一可執行的地方） | [源] |
| 電池 | 4 顆 3 號（AA），最長約 30 小時 | [源] |
| 銷量 | GB + GBC 合計 118.69 million（至 2003 年停產） | [源] |
| 開機 ROM | 內建 256 bytes，開機播 logo 與「po-ling」音、驗卡帶內的任天堂 logo 與標頭檢查碼 | [源] |

### 2.2 PPU（圖形）
| 項目 | 數值 | 標註 |
|---|---|---|
| 磁磚 | 8×8 像素，**2 bpp**，每片 16 bytes | [源] |
| 圖樣表 | VRAM 內兩塊 tileset 區 | [源] |
| 背景圖層 | 256×256 像素（32×32 磁磚）可捲動地圖 | [源] |
| Window 圖層 | 160×144 的**不捲動**覆蓋層（做 HUD / 對話框最省事） | [源] |
| 精靈總數 | 40 個 | [源] |
| 每掃描線精靈 | 10 個 | [源] |
| 精靈尺寸 | 8×8 或 8×16（全域二選一） | [源] |
| OAM | 在 PPU 內，靠 DMA 從 RAM / ROM 灌入 | [源] |
| 背景調色盤 | 1 組（BGP），4 色取自 4 階灰 | [源] |
| 精靈調色盤 | 2 組（OBP0 / OBP1），各 3 色 + 1 透明 | [源] |
| 中斷 | H-Blank、V-Blank、OAM Search（可做分行捲動、分行換調色盤） | [源] |

> **重點**：GB 的精靈「每行 10 個」比 NES 的「每行 8 個」寬鬆，而且 **不會像 NES 那樣強制閃爍**，
> 但總數只有 40（NES 64）。所以 GB 適合「角色大、雜兵少」的設計，NES 適合「小角色、雜兵多」。[推論]

### 2.3 GB 的經典技法
| 技法 | 說明 | 標註 |
|---|---|---|
| 分行捲動（HBlank 改 SCX） | 做水波、賽車路面、標題波浪字 | [推論]（原理同 NES 的 raster split [源]） |
| Window 當 HUD | 直接把狀態列鎖在螢幕下 / 上緣，不吃背景捲動 | [源] |
| 8×16 精靈模式 | 角色高度 16 px 時精靈數減半，是最常見的省 OAM 手段 | [推論] |
| DMA 必須在 HRAM 執行 | OAM DMA 期間匯流排被佔住，程式碼必須搬到 HRAM | [源] |

## 3. Game Boy Color（CGB，1998）

### 3.1 基本資料
| 項目 | 數值 | 標註 |
|---|---|---|
| 發售日 | 日本 1998-10-21 / 北美 1998-11-18 / 歐洲 1998-11-23 | [源] |
| CPU | 同 SM83；一般 4.194304 MHz，**倍速模式 8.388608 MHz** | [源] |
| 螢幕 | 2.3 吋 TFT LCD，160×144 | [源] |
| 色彩 | 同畫面最多 **56 色**，調色盤庫 **32768 色**（15-bit） | [源] |
| WRAM | 32 KB（以 SVBK 暫存器分頁） | [源] |
| VRAM | 16 KB（兩個 8 KB bank，以 VBK 切換） | [源] |
| 開機 ROM | 2 KB；會判斷 DMG / CGB 模式，並替黑白遊戲自動配色 | [源] |
| 電池 | 2 顆 AA，約 10 小時 | [源] |
| 卡帶上限 | 加 mapper 後最大 8 MB | [源] |

### 3.2 相對 GB 的圖形強化
| 強化 | 內容 | 標註 |
|---|---|---|
| 調色盤 | 16 組（背景 8 + 精靈 8），每組 4 色，色源 32768 色 | [源] |
| 精靈調色盤 | 由 2 色變 **3 色 + 1 透明** | [源] |
| 磁磚翻轉 | 背景 / Window 磁磚可**水平與垂直翻轉**（NES 背景做不到，只有精靈可以） | [源] |
| VRAM bank 1 | 存放每格的屬性（調色盤編號、bank、翻轉、優先權） | [源] |
| HDMA | 一般 DMA 外多了 **H-Blank DMA**，可在每條掃描線的空檔搬資料（做漸層背景、卷軸串流） | [源] |
| 倍速模式 | CPU 加倍但**音訊不加速**（音高會變，不是品質變好，所以音樂驅動需配合調整） | [源] |
| 紅外線 | LED + 光電晶體，單一 RP 暫存器，無內建協定，需自行實作 | [源] |

> **對本專案的意義**：GBC 是「限制最甜」的一台——解析度小好畫、色彩夠用（每磁磚 4 色但可自選 32768 色中的任意 4 色），
> 而且工具鏈（GBDK-2020 / GB Studio）最成熟。[推論]

## 4. Game Boy Advance（AGB，2001）

### 4.1 基本資料
| 項目 | 數值 | 標註 |
|---|---|---|
| 發售日 | 日本 2001-03-21 / 北美 2001-06-11 / PAL 2001-06-22 | [源] |
| CPU | ARM7TDMI @ **16.78 MHz**，支援 16-bit Thumb 指令集 | [源] |
| 相容用 CPU | 內含 Sharp SM83 @ 8.4 / 4.2 MHz，**兩顆絕不同時執行** | [源] |
| 螢幕 | 2.9 吋 TFT LCD，**240×160**，~60 Hz | [源] |
| 色彩 | 15-bit，32768 色 | [源] |
| 銷量 | GBA 家族約 81.51 million（至 2010） | [源] |
| 電池 | 2 顆 AA，最長約 15 小時 | [源] |
| 變體 | GBA SP（2003，翻蓋 + 前光）、SP 背光版（2005）、Game Boy Micro（2005，不相容 GB / GBC） | [源] |

### 4.2 記憶體（依速度排序）
| 區域 | 大小 | 匯流排 | 備註 | 標註 |
|---|---|---|---|---|
| IWRAM | 32 KB | 32-bit | 最快，放熱迴圈與 ARM 程式碼 | [源] |
| VRAM | 96 KB | 16-bit | 背景 64 KB + 精靈 32 KB | [源] |
| EWRAM | 256 KB | 16-bit | 主要工作記憶體，有等待狀態 | [源] |
| Palette RAM | 1 KB | 16-bit | 每調色盤 256 項 | [源] |
| OAM | 1 KB | 32-bit | **128 個精靈項目** | [源] |
| Game Pak ROM | 最大 32 MB | 16-bit + prefetch（8×16-bit） | 25-bit 位址、最低位固定 0 | [源] |
| Game Pak RAM | — | 8-bit | 存檔用 | [源] |

> 因為「大部分記憶體只有 16-bit 匯流排」，GBA 程式**預設用 Thumb 編譯**、只把熱點放 IWRAM 用 ARM。[源]

### 4.3 影像模式
| 模式 | 型態 | 背景數 | 特性 | 標註 |
|---|---|---|---|---|
| Mode 0 | 磁磚 | 4 層 | 全部只能捲動 | [源] |
| Mode 1 | 磁磚 | 3 層 | 其中 1 層可仿射（縮放 / 旋轉） | [源] |
| Mode 2 | 磁磚 | 2 層 | 兩層都可仿射 | [源] |
| Mode 3 | Bitmap | — | 240×160，16 bpp 單緩衝，可同時 32768 色 | [源] |
| Mode 4 | Bitmap | — | 8 bpp，**雙緩衝** | [源] |
| Mode 5 | Bitmap | — | 16 bpp，**半解析度（160×128）雙緩衝** | [源] |

磁磚：8×8，**4 bpp（32 bytes）或 8 bpp（64 bytes）**，以 16 KB charblock 為單位。[源]
精靈：最大 64×64；仿射精靈可放大到 128×128。[源]
特效：**Mosaic（馬賽克）、Colour blending（Alpha 混色）、Windowing（可程式矩形視窗）**。[源]
磁磚模式下同畫面最多 **511 色**（背景 256 + 精靈 256 − 共用透明色），Bitmap 模式可全 32768 色。[源]

## 6. 圖形子系統逐項比較

### 6.1 「一格磁磚可用幾色」
| 機種 | 每磁磚色數 | 調色盤怎麼指定 | 標註 |
|---|---|---|---|
| NES | 3 色 + 共用背景色 | 以 **16×16 像素（2×2 磁磚）為單位**的 attribute table，這是 NES 美術最大的枷鎖 | [源] |
| GB | 4 階灰（全畫面同一組） | 無選擇 | [源] |
| GBC | 4 色 | **每一格磁磚**都能獨立指定 8 組背景盤之一 | [源] |
| GBA | 16 色（4bpp）或 256 色（8bpp） | 每一格磁磚獨立指定 16 組之一 | [源] |

> 這張表是三機美術風格差異的根源：NES 的「格子配色」問題在 GBC 完全消失（改成逐磁磚選盤），
> 所以 GBC 的像素圖可以做細緻漸層，而 NES 必須用抖色 / 對齊 16×16 來遮掩。[推論]

### 6.2 視野換算
以 16×16 磁磚的角色為基準：

| 機種 | 畫面可見磁磚（16×16 格） | 感受 | 標註 |
|---|---|---|---|
| NES | 16 × 15（256×240） | 標準橫捲視野 | [源] |
| GB / GBC | **10 × 9**（160×144） | 只有 NES 的 **37.5% 面積**，橫向看得到的東西少 6 格 | [推論]（由解析度換算） |
| GBA | 15 × 10（240×160） | 橫向接近 NES、縱向只有 2/3 | [推論] |

實務上 GB 遊戲常把角色縮到 **16×16 以下（甚至 8×16）**，或把磁磚視為 8×8 來排關卡，才不會塞爆畫面。[推論]

## 7. 音源比較

| 聲道 | NES 2A03 | GB / GBC APU | GBA | 標註 |
|---|---|---|---|---|
| 1 | 脈衝 1（4 種工作週期 + 掃頻 + 包絡） | 脈衝 1（**有 sweep**） | 同 GB（相容 PSG） | [源] |
| 2 | 脈衝 2 | 脈衝 2 | 同左 | [源] |
| 3 | 三角波（固定音量） | **波表（32 個 4-bit 取樣，可自訂波形）** | 同左 | [源] |
| 4 | 雜訊（含週期模式） | 雜訊（**兩種音色**） | 同左 | [源] |
| 5 | DPCM（7-bit 取樣 ~15.74 kHz） | — | **Direct Sound A / B：2 條 8-bit 有號 PCM，取樣率可變（理論上限 65 kHz）** | [源] |
| 擴充 | Famicom 卡帶腳位可外掛（VRC6 / N163 / FDS…） | 卡帶腳位有 1 條額外聲道（**商業作幾乎沒用**） | — | [源] |

設計含意：
- **GB 的波表聲道是它最獨特的武器**：可以塞進自製波形做出接近弦樂 / 低音 / 人聲的音色，這是 NES 三角波（音量固定、只能當貝斯）做不到的。[推論]
- **GBA 可以直接播 8-bit 取樣**，所以 GBA 音樂實務上是「軟體混音器 + tracker 模組（Maxmod / MOD / XM）」，不是純 PSG。[源]
- 若要在瀏覽器模擬「掌機音色」：GB 用 2 脈衝 + 1 自訂波表 + 1 雜訊；NES 用 2 脈衝 + 三角 + 雜訊 + 取樣。兩者聽感差別主要在第 3 聲道。[推論]

## 8. 記憶體與卡帶 / 存檔

| 項目 | GB | GBC | GBA | 標註 |
|---|---|---|---|---|
| 無 mapper 上限 | 32 KB | 32 KB | — | [源] |
| 有 mapper 上限 | 1 MB（MBC1/2/3/5） | 8 MB | 32 MB（25-bit 位址） | [源] |
| 存檔 | 電池 SRAM（MBC3 可加 RTC 即時鐘） | 同左 | SRAM ≤64 KB / Flash（寫入次數有限）/ EEPROM ≤8 KB（序列介面） | [源] |

## 9. 通訊與多人

| 機種 | 介面 | 速度 | 人數 | 標註 |
|---|---|---|---|---|
| GB | 6-pin 連線纜（SPI，主 / 從） | 8 Kbit/s（1 KB/s） | 2；4-Player Adapter 可 4 人 | [源] |
| GBC | 同上 + 高速模式 | 最高 512 Kbit/s（64 KB/s） | 同上 | [源] |
| GBC | 紅外線（RP 暫存器，無協定） | — | 2 | [源] |
| GBA | 新式連線纜（紫端為主機、灰端為從機），同步 SPI 或非同步 UART | 最高 250 KB/s | 最多 4 台菊鏈 | [源] |
| GBA | **Single-Pak Link / Multiboot**：一張卡帶靠 EXT 埠把程式送給其他機器 | — | 最多 4 | [源] |

> Multiboot 是 GBA homebrew 很有趣的一條路：可以做「一台有卡帶、其他人空機」的多人 demo。[推論]

## 11. 「像素風掌機遊戲」與 NES 的設計差異

### 11.1 螢幕小 → UI 與視野
| 面向 | NES | GB / GBC | 建議做法 | 標註 |
|---|---|---|---|---|
| 可見格數（16px 磁磚） | 16×15 | 10×9 | 掌機關卡「往上下發展」比「往左右拉長」更有感 | [推論] |
| HUD | 常佔畫面上 / 下 16～32 px | 用 **Window 圖層**，且只放 2～3 個數字 | HUD 不超過 16 px 高；血量用圖示不用數字 | [推論]（Window [源]） |
| 字體 | 8×8 點陣，一行 32 字 | 8×8 一行只有 **20 字** | 對話盡量 2 行 × 18 字內；中文用 12×12 會只剩 13 字 | [推論] |
| 鏡頭 | 可預看前方 7～8 格 | 只能預看 4～5 格 | **降低角色移動速度**或加「主動預看」（按上看遠方） | [推論] |
| 敵人預告 | 靠畫面邊緣進場 | 邊緣太近，容易變成無預警受擊 | 敵人進場要有 0.5 秒的出現動畫 / 音效當預告 | [推論] |

### 11.2 按鍵少
| 機種 | 按鍵 | 標註 |
|---|---|---|
| NES 手把 | D-Pad + A / B + Select / Start（2 動作鍵） | [推論] |
| GB / GBC | D-Pad + A / B + Select / Start（2 動作鍵，**與 NES 相同**） | [源]（手感上等同 NES [推論]） |
| GBA | D-Pad + A / B + **L / R 肩鍵** + Select / Start（4 動作鍵） | [推論] |

含意：
- GB / GBC 的按鍵數與 NES 一樣，所以 NES 的操作設計可以**直接搬**。[推論]
- GBA 多了 L / R，才適合「切換武器 / 衝刺 / 鎖定」這類第三、四動作。若打算未來上 GBA，設計時可預留兩個可選鍵位。[推論]
- 掌機是單手托著玩，**長按 + 方向的複合指令要少**（例如同時按住 B 跑步再按 A 跳，在 GB 上比家機累）。[推論]

### 11.3 通訊線多人
| 面向 | 說明 | 標註 |
|---|---|---|
| 頻寬 | GB 1 KB/s、GBC 64 KB/s、GBA 250 KB/s | [源] |
| 設計含意 | GB 時代只能同步「按鍵輸入」或「少量事件」，不可能同步整個世界狀態；所以對戰式（Tetris、對戰寶可夢）比合作橫捲可行 | [推論] |
| GBA Multiboot | 一張卡帶可以把小程式送給另外 3 台，適合做「派對小遊戲」 | [源] |
| 對本專案 | 若做瀏覽器版，「連線對戰」可用 WebRTC / 共享鍵盤模擬；但**真 ROM 的連線纜開發與測試成本很高（需要模擬器 link 支援，如 BGB）**，第一版不建議 | [推論]（BGB link 支援 [源]） |

### 11.4 電池續航 → 遊戲節奏
| 面向 | 說明 | 標註 |
|---|---|---|
| 續航 | GB 30 h / GBC 10 h / GBA 15 h | [源] |
| 遊玩情境 | 通勤、排隊、短時段 | [推論] |
| 設計含意 1 | **單關 3～5 分鐘可結束**，不要做 15 分鐘無存檔點的關卡 | [推論] |
| 設計含意 2 | 存檔需求高 → 電池 SRAM 幾乎是必備（GB 無電池就只能用密碼制） | [推論]（SRAM [源]） |
| 設計含意 3 | 暫停要能「隨時中斷、關機再回來」→ 中途存檔（suspend save）比關卡存檔友善 | [推論] |
| 設計含意 4 | 早期 GB / GBA 無背光 → 美術要**高對比**、不要靠暗部細節傳達資訊 | [推論]（GBA SP 才加前光 [源]） |

### 11.5 一張「移植難度」速查
把一款 NES 風格遊戲往掌機搬時，會踩到的坑：

| 原本仰賴 | GB 上的狀況 | 解法 | 標註 |
|---|---|---|---|
| 16×15 格視野 | 只剩 10×9 | 角色縮成 12×12 或鏡頭拉遠（用 8×8 磁磚排關） | [推論] |
| 每掃描線 8 精靈（習慣閃爍） | 每行 10 個但**總數只有 40** | 減少同屏敵人到 4～6 個 | [推論]（數值 [源]） |
| 4 組精靈調色盤 | GB 只有 2 組灰階 | 靠造型辨識而非顏色辨識（輪廓要夠不同） | [推論]（數值 [源]） |
| 三角波貝斯 | 沒有三角波 | 用波表聲道自製三角 / 鋸齒波形 | [推論]（波表 [源]） |
| DPCM 鼓組 | 沒有取樣聲道 | 用雜訊聲道 + 短包絡做鼓 | [推論] |
| 32 字一行文字 | 只剩 20 字 | 重寫所有文案；中文改用 8×8 或縮字距 | [推論] |

## 12. 給本專案的可操作結論

1. **若目標是「像素風 + 電子音樂 + 能在模擬器跑」**，GBC 是三台裡開發成本 / 表現力比最好的：
   逐磁磚 4 色自選（美術自由度遠勝 NES）、工具鏈成熟（GBDK-2020 / GB Studio）、ROM 上限 8 MB。[推論]
2. **若目標是「最正統的紅白機味」**，仍應選 NES：256×240 與 2A03 音色是不可替代的識別度。[推論]
3. **若目標是「效果上限最高」**，GBA：仿射縮放旋轉、Alpha 混色、PCM 音樂，幾乎可以做出 16-bit 主機等級畫面。
   代價是「像素風」的純度會下降（容易變成「小尺寸的 SNES 遊戲」）。[推論]
4. **瀏覽器版的自我約束建議**（若走假復古路線，見文件 08）：
   - 走 NES 味：內部解析度 256×224、4 組 3 色調色盤、每 16×16 一組色、同屏精靈 ≤ 64。
   - 走 GB 味：內部解析度 160×144、全畫面 4 階（例如 `#0f380f #306230 #8bac0f #9bbc0f`）、同屏精靈 ≤ 40。
   - 走 GBC 味：160×144、每 8×8 磁磚可選 8 組 4 色盤之一。
   （以上調色盤數值為社群常用的 DMG 綠色近似值，屬 [推論]；硬體本身只規定「4 階灰」[源]。）
5. **不論哪條路，關卡長度都要壓在 3～5 分鐘**，並提供隨時可續玩的存檔，這是掌機遊玩情境的硬需求。[推論]
