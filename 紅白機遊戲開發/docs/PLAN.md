# 實作計畫：用現代程式「原汁原味」還原紅白機（2026-09-14 改版）

> 使用者定調：**不做卡帶、不做 NES ROM**。像 `../卡比之星` 一樣用 HTML5 Canvas + Web Audio 寫，但目標是把紅白機的畫面、手感、聲音還原到「原汁原味」——這是對實作能力的考驗。
> 研究文件（`docs/research/`）是規格來源：硬體限制（01）、手感數字（03）、設計模式（04）、美術規範（05）、2A03 音訊（06）。素材一律原創（美術 / 音樂 / 關卡 / 名稱），機制與手感忠實還原。

## 1. 目標與「原汁原味」的定義（可驗證）
| 面向 | 還原標準（測試會驗） | 來源 |
|---|---|---|
| 畫面 | 內部 256×240（顯示裁 224）、整數倍放大、無平滑；只有 **64 色 NES 調色盤**（含 $0D 禁用、NTSC 色碼表）；背景 4 組 + 精靈 4 組調色盤、每組 3 色 + 共用底色 → **同屏 ≤ 25 色**；背景配色以 **16×16 屬性區塊**為單位；8×8 磁磚、名稱表 / 屬性表資料結構 | 01 §3、05 §1 |
| 精靈 | 64 個 OAM、8×8 / 8×16 模式、**每掃描線 8 個上限，超過就閃爍**（輪替繪製順序）、精靈優先權 / 翻轉、大魔王用背景層 | 01 §3、05 §3 |
| 捲動 | 單層背景 + 名稱表鏡像；狀態列用「掃描線分割」（模擬 sprite 0 / IRQ）；視差只能靠逐線捲動與調色盤循環 | 01 §3、05 §5 |
| 節奏 | 固定 60.0988 Hz 邏輯步、每幀一次輸入取樣、**定點數（8.8 / 1/16 px）物理**、無 delta-time 補間；可選 NTSC 抖動 / PAL 50Hz 模式 | 01 §2、03 |
| 聲音 | **2A03 五聲道軟體模擬**：方波 4 種占空比 + 掃頻 + 包絡、三角波固定 32 階無音量、雜訊 15-bit LFSR 長 / 短模式（NTSC 週期表）、DPCM 1-bit 差分、**非線性混音公式**、frame counter 240Hz；音效搶聲道規則；音樂驅動吃「FamiTracker 式」pattern 資料（每幀為單位、琶音 / 顫音 / 占空比包絡效果） | 06 §1、§2、§6 |
| 手感 | 以研究的反組譯數字為準：走 1.5 / 跑 2.5 px/f、加速度表、跳躍雙重力（按住 / 放開）、無敵幀、輸入延遲 1 幀、DAS 等 | 03 各篇 |
| 內容規格 | 主角 16×24（8×16 精靈）、敵人 16×16、走路 3 幀、狀態列 8×8 字型、密碼 / 電池存檔皆以 localStorage 模擬 | 05 §3、§4、04 §8 |
| 可選外觀 | CRT 濾鏡（掃描線 / 色暈 / 桶形）可開關；預設關 | 01 §7 |

「原汁原味」不是只有像素風，而是**引擎層就受 PPU / APU 同樣的限制**：畫不出限制外的東西，聲音只能由五聲道發出。

## 2. 架構：先做「NES 核心」引擎，再做遊戲
```
紅白機遊戲開發/
  engine/            NES 核心（獨立、可被多款遊戲共用；無外部相依）
    ppu.js           名稱表 / 屬性表 / 調色盤 / OAM / 掃描線渲染器（每幀輸出 256×240 到 Canvas）、8 精靈上限與閃爍、分割捲動
    apu.js           2A03 五聲道模擬（AudioWorklet 或 ScriptProcessor 產生 PCM；離線渲染供測試）+ 音樂驅動（pattern / 效果指令）+ 音效優先權
    cpu_timing.js    60.0988Hz 固定步、幀預算計數（可選：模擬 VBlank 寫入預算，超過就丟幀，讓「只能改 160 bytes」成為真限制）
    chr.js           CHR「圖樣表」：以程式手繪的 8×8 2bpp 磁磚（文字格式，同卡比 KB.sprite 但強制 2bpp）+ bank 切換
    input.js         手把 8 鍵、每幀取樣、輸入記錄 / 重播（自動測試用）
    fixed.js         定點數工具（8.8、1/16 px）
    nes_lint.js      執行期 / 建置期檢查：同屏色數、每線精靈數、調色盤越界、非 8px 對齊、非 64 色 → 直接報錯或畫洋紅
  games/<遊戲名>/     每款遊戲：關卡 / 實體 / 美術（CHR 資料）/ 音樂 pattern / 測試
  tools/             shot.py（沿用卡比：Playwright 截圖 + 除錯 API）、apu_render.py（離線渲染 wav 比對頻譜）、lint、playthrough 機器人、build.py（單檔）
  docs/research/     規格來源
```
- 沿用卡比之星的開發方式：`?debug=1` 除錯 API（goto / step / press / state）、截圖必看圖、多 agent 檔案所有權矩陣、PROGRESS 回報協定、每輪 QA。
- 卡比引擎的哪些可搬：截圖 / 測試 / 打包工具鏈、輸入層、場景管理、文字工具（8×8 點陣）；**不搬**卡比的繪製與音訊（它們沒有 PPU / APU 限制）。

## 3. 第一款遊戲：橫向平台動作（工作名《星塵勇者》，名稱可改）
選它的理由：研究中手感數字最完整（超級瑪利歐 1 / 3 的反組譯常數、洛克人 2 的傷害表、惡魔城的分段傷害），最能驗證「原汁原味」。
- 骨架：SMB1 的物理（1/16 px 速度、雙重力、加速度表、動量跳）+ SMB3 的世界地圖與道具存量 + 洛克人的選關 / 武器切換 + 惡魔城的副武器（皆為機制借鑑，內容原創）。
- 規模：8 世界 × 4 關（含 1 城堡 / 魔王關）、每關 3~4 個房間（水平捲動為主，含垂直 / 自動捲動 / 水中各 ≥2 關）、敵人 24 種、魔王 8 + 最終、道具 6、隱藏區 / 暖管式捷徑、密碼 + 存檔。
- 音樂：地面 / 地下 / 水中 / 城堡 / 魔王 / 無敵 / 過關 / 死亡 / 結局，全部以 APU pattern 撰寫（研究 06 的技法：琶音、回音軌、三角波低音、雜訊鼓）。
- 驗收（除截圖外）：
  1. 手感測試：從靜止到全速幀數、4 格 / 5 格跳高度、跑跳距離、無敵幀數與研究表相符（±1 幀）。
  2. PPU 測試：任一幀同屏色 ≤ 25、每線精靈 > 8 時確實閃爍、無非 64 色像素（lint 逐像素掃描截圖）。
  3. APU 測試：離線渲染每首曲 10 秒，頻譜只含五聲道成分；音效搶佔時音樂確實少一軌。
  4. 自動通關機器人跑完 32 關。

## 5. 與卡比之星的差異（避免混淆）
| | 卡比之星 | 紅白機專案 |
|---|---|---|
| 目標 | 好玩、腦洞、特效多 | 忠實還原限制與手感 |
| 繪製 | 任意色、任意層、全畫面特效 | PPU 模型：25 色 / 8 精靈 / 一層背景 |
| 音訊 | Web Audio 自由合成 | 2A03 五聲道模擬，pattern 驅動 |
| 物理 | 浮點、dt=1 幀 | 定點數、反組譯常數 |
| 檢查 | 測試 + 截圖 | 測試 + 截圖 + **nes_lint 逐像素 / 逐聲道** |
