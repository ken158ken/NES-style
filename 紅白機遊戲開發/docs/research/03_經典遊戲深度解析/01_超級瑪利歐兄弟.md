# 01 超級瑪利歐兄弟（Super Mario Bros. / スーパーマリオブラザーズ，1985）

## 摘要（10 行內）
1. 任天堂 R&D4 於 1985 年推出的橫向捲軸平台遊戲，是 NES 平台動作遊戲的「文法制定者」。
2. 卡匣只有 **32 KiB 程式 + 8 KiB 圖形（NROM / mapper 0）**，音樂塞進去後只剩約 20 bytes 空間。[源]
3. 手感是全作核心：速度以 **1/16 像素/幀** 為單位，走路上限 1.5 px/f、跑步上限 2.5 px/f。[源：反組譯]
4. 跳躍為「可變高度」：放開 A 且已上升 ≥1 px 就切換成大重力，做出從 1.1 格到 5 格的連續跳躍高度。[源：反組譯]
5. 受傷無敵 168 幀（約 2.8 秒）、星星無敵 735 幀（約 12.2 秒），皆由 21 幀的「間隔計時器」驅動。[源：反組譯]
6. 8 世界 × 4 關 = 32 關，無存檔、無密碼（原版），靠 Warp Zone 做捷徑。[源]
7. 敵人只有 10 餘種但行為全部互補：教踩、教閃、教等、教不能踩。[推論]
8. 魔王只有 1 種（庫巴 + 8 種投射物組合），用「假魔王 × 7 + 真魔王 × 1」省容量。[源]
9. 世界 1-1 是史上最常被引用的「不寫字的教學關」。[源]
10. 全球累計 4,024 萬套（NES 原版），總計逾 5,800 萬套（含移植）。[源]

## ② 核心迴圈與操作

### 按鍵配置
| 按鍵 | 功能 |
|---|---|
| ←→ | 走 / 跑（配合 B） |
| ↓ | 蹲（僅超級 / 火焰狀態）、下水管 |
| ↑ | 上水管 / 爬藤蔓 |
| A | 跳（**可變高度**） |
| B | 加速（Dash）/ 射火球（火焰狀態） |
| Start | 暫停 |

### 速度與加速度（單位：速度值 = 1/16 px/frame）[源：SMBDIS.ASM 反組譯]

| 表 | 位址標籤 | 數值 | 換算 |
|---|---|---|---|
| 向右最高速 | `MaxRightXSpdData` | `$28 / $18 / $10 / $0c` | 跑 2.5 / 走 1.5 / 水中 1.0 / 進場演出 0.75 px/f |
| 向左最高速 | `MaxLeftXSpdData` | `$d8 / $e8 / $f0` | −2.5 / −1.5 / −1.0 px/f |
| 加速度 / 摩擦 | `FrictionData` | `$e4 / $98 / $d0` | 228 / 152 / 208（單位 1/256 速度值 per frame） |

換算後的體感：
- 跑步加速度 = 228/256 ≈ 0.891 速度值/幀 → **從靜止到 2.5 px/f 需約 45 幀（0.75 秒）**。[推論：由 40 ÷ 0.891 計算]
- 走路加速度 = 152/256 ≈ 0.594 速度值/幀 → **到 1.5 px/f 需約 40 幀（0.67 秒）**。[推論]
- 若「面向方向 ≠ 移動方向」（煞車 / 轉向），加速度值會 **左移一位＝×2**，所以急停與轉身比加速快一倍。[源：`asl FrictionAdderLow` / `rol FrictionAdderHigh`]
- **空中控制規則**：在空中（`Player_State ≠ 0`）時，若水平速度 ≥ `$19`（1.5625 px/f）才沿用跑步上限與跑步加速度；低於此值只能用走路上限。這就是「走著起跳無法在空中加速到全速」的成因。[源]

### 跳躍（單位：重力值 = 1/256 px/frame²）[源：反組譯]

起跳時依 `Player_XSpeedAbsolute` 分成 5 段（索引 0–4）：

| 索引 | 水平速度門檻 | 初速 `PlayerYSpdData` | 按住 A 重力 `JumpMForceData` | 放開 A 重力 `FallMForceData` | 理論最高跳躍高度 |
|---|---|---|---|---|---|
| 0 | < `$09`（0.56 px/f） | −4 px/f | `$20` = 0.125 px/f² | `$70` = 0.4375 px/f² | 64 px ＝ **4 格磚** |
| 1 | < `$10`（1.0） | −4 | `$20` = 0.125 | `$70` = 0.4375 | 64 px（4 格） |
| 2 | < `$19`（1.5625） | −4 | `$1e` = 0.1172 | `$60` = 0.375 | 約 68 px（4.3 格） |
| 3 | < `$1c`（1.75） | −5 | `$28` = 0.15625 | `$90` = 0.5625 | 80 px ＝ **5 格磚** |
| 4 | ≥ `$1c` | −5 | `$28` = 0.15625 | `$90` = 0.5625 | 80 px（5 格） |
| 5 / 6 | 游泳 / 漩渦 | −2 / −1 | `$0d` / `$04` | `$0a` / `$09` | — |

- **可變高度跳的實作方式**：每幀檢查「A 目前按住 **且** 上一幀也按住」；若條件不成立，且 `起跳點 Y − 目前 Y ≥ DiffToHaltJump（＝1 px）`，就把重力換成 `VerticalForceDown`。也就是**離地 1 像素後放手即進入快速下墜**。[源]
- 因此最短跳（點一下 A）≈ 16 ÷ (2 × 0.4375) ≈ **18 px（約 1.1 格磚）**。[推論]
- 起跳後不會鎖住水平朝向；空中可轉向，但受上述空速門檻限制。[源]

### 無敵幀與計時器
- 遊戲有 **21 幀的「間隔計時器」節拍**：`IntervalTimerControl` 由 `$14`(20) 每幀遞減，歸零後重設並讓長計時器前進一格 → 每 21 幀一跳。[源]
- **受傷（大變小）無敵**：`InjuryTimer = $08` → 8 × 21 = **168 幀 ≈ 2.80 秒**。[源＋推論換算]
- **星星無敵**：`StarInvincibleTimer = $23`(35) → 35 × 21 = **735 幀 ≈ 12.2 秒**；剩 8 格以下時閃爍速度改變作為預警。[源]
- 這個 21 幀節拍同時是速通界著名的「framerule」：過關時間會被進位到下一個 21 幀邊界。[源]

### 輸入緩衝
- 原版**沒有跳躍輸入緩衝、沒有 coyote time**：離開地面那一幀之後按 A 不會起跳。[推論：反組譯中起跳條件僅檢查 `Player_State == 0`]
- 但有「A 需連續兩幀成立」的判定，等於天然的 1 幀防彈跳濾波。[源]

## ③ 關卡結構

| 項目 | 內容 |
|---|---|
| 世界數 | 8 |
| 每世界關數 | 4（x-1 ~ x-4） |
| 總關數 | 32 |
| 捲動 | **僅水平、單向**；畫面不可往左回捲（相機只前進不後退） |
| 每關長度 | 多數約 2.5–3.5 個「區段」；以 16 px 磚為單位，典型關卡寬約 200–220 格磚 [推論] |
| 檢查點 | 每關 1 個中途點（通過後死亡從中途重生）；`x-4` 城堡關無中途點 [源] |
| 存檔 / 密碼 | 無 |
| 續關 | Game Over 後按住 A 再 Start 可從該世界第 1 關重來（隱藏指令）[源] |

### 關卡類型
1. **地上（Overworld）**：藍天、磚塊、水管；教學與節奏關。
2. **地下（Underground）**：黑底單色調色盤，取磚塊金幣、走水管。
3. **水中（Underwater）**：重力換成游泳物理（初速 −2、重力 `$0d`），不可踩敵。
4. **空中 / 樹上（Athletic）**：小平台、彈簧、跳躍精度關。
5. **城堡（Castle, x-4）**：火棒、熔岩、假庫巴；固定為每世界結尾。

### 分支與祕密
- **Warp Zone**：1-2（世界 2/3/4）、4-2（世界 5/6/7）、3-1 / 4-2 的藤蔓路線（世界 5）。[源]
- **隱藏 1-UP 磚**、**藤蔓天空金幣房**、**磚塊金幣泉（連打同一磚可持續出金幣約 5 秒）**。[源]
- **Minus World（−1）**：1-2 結尾用磚塊角落穿牆進入的著名 bug 關。[源]
- 世界 x-4 通關才會推進世界計數；8-4 需走正確水管迷宮順序，否則會迴圈。[源]

## ④ 敵人設計（代表 10 種）

| # | 敵人 | 行為模式 | 教學意義 |
|---|---|---|---|
| 1 | 栗寶寶 Goomba | 直線走、碰牆轉向、會走下平台；速度 0.5 或 0.75 px/f（`NormalXSpdData = $f8 / $f4`）[源] | **教「踩」**：第一個出現、最慢、一踩必死 |
| 2 | 綠烏龜 Koopa Troopa | 走路；踩一下變龜殼、再踢出去變滑行道具 | 教「敵人有第二階段」與「敵人可當武器」 |
| 3 | 紅烏龜 | 同上，但**不會走下平台**（碰到邊緣會轉向） | 教「同外型不同顏色＝不同規則」，顏色即語意 |
| 4 | 慢慢龜 Buzzy Beetle | 龜殼型、**免疫火球** | 教「火球不是萬能」，強迫換用踩 |
| 5 | 刺龜 Spiny | 不可踩（踩了受傷），由 Lakitu 投擲 | 教「不是所有東西都能踩」，建立「尖刺 ＝ 危險」視覺語彙 |
| 6 | 砲彈庫巴 Lakitu | 在雲上跟隨玩家 X 座標、週期性丟刺龜蛋 | 教「垂直方向威脅」與「要用跑的甩開」 |
| 7 | 食人花 Piranha Plant | 週期性從水管出入；**玩家站在水管上時不出來** | 教「等待節奏」；隱含規則讓玩家自己發現 |
| 8 | 砲彈刺客 Bullet Bill | 從砲台水平射出、不受地形影響 | 教「必須跳過或踩上去」，引入可踩的投射物 |
| 9 | 錘子兄弟 Hammer Bro | 左右小幅走動 + 拋物線錘子 + 會跳上下平台（`HammerBroJumpLData = $20 / $37`）[源] | 教「上下都要顧」、首個需要主動壓迫的敵人 |
| 10 | 火棒 Fire Bar | 固定軸心旋轉的火焰鏈（純機關） | 教「讀取旋轉週期」，把時間軸變成空間障礙 |

**設計規律**：每種敵人只有 **1 條規則**，難度靠「組合 + 地形」而非敵人本身複雜化。[推論]

## ⑤ 魔王設計

本作只有一個魔王實體：**庫巴（Bowser / 大魔王クッパ）**，出現在 x-4。

| 世界 | 型態 | 攻擊 | 破法 |
|---|---|---|---|
| 1-4 | 假庫巴（實為栗寶寶變身） | 只吐火 | 5 發火球 或 走到斧頭切橋 |
| 2-4 | 假庫巴（烏龜） | 吐火 | 同上 |
| 3-4 | 假庫巴（慢慢龜） | 吐火 + **開始跳躍** | 同上 |
| 4-4 | 假庫巴（刺龜） | 吐火 + 跳 + **丟錘子** | 同上 |
| 5-4 | 假庫巴（Lakitu） | 錘子密度上升 | 同上 |
| 6-4 | 假庫巴（刺龜） | 錘子 + 移動範圍變大 | 同上 |
| 7-4 | 假庫巴（錘子兄弟） | 最密錘子 | 同上 |
| 8-4 | **真庫巴** | 火 + 錘 + 跳，血量最高 | 斧頭 或 火球 |

- **兩種解法並存**：斧頭（零技巧、任何狀態可用）與火球（需保持火焰狀態）——同一個魔王同時服務新手與熟練玩家。[推論]
- 階段化不是靠 HP 條，而是靠 **世界編號決定攻擊組合**：同一段程式碼 + 一張參數表＝ 8 個「不同」魔王。這是極省容量的作法。[源＋推論]

## ⑥ 道具與成長

| 道具 | 效果 | 取得 |
|---|---|---|
| 超級蘑菇 | 小 → 大（多一次受傷緩衝、能撞碎磚） | `?` 磚（小狀態時必定是蘑菇） |
| 火之花 | 大 → 火焰（B 射火球，畫面最多 2 顆） | `?` 磚（已是大的狀態時出現） |
| 星星 | 12.2 秒無敵、碰撞即殺、連鎖加分 | 特定磚 |
| 1-UP 蘑菇 | 加一條命 | 隱藏磚 / 連續踩敵 / 100 金幣 |
| 金幣 | 100 枚 = 1UP | 磚、金幣、隱藏房 |

### 成長 = 「狀態機」而非數值
小 → 大 → 火焰，共 3 段；受傷一律退一階，火焰受傷直接退到小。**沒有 HP 數值**，玩家用角色大小就能讀出自己的生命狀態。[源]

### 分數規則（連續踩敵，不落地）[源：`ScoreUpdateData`]
`100 → 200 → 400 → 500 → 800 → 1000 → 2000 → 4000 → 5000 → 8000 → 1UP`

### 旗杆分數 [源：`FlagpoleScoreMods / FlagpoleScoreDigits`]
由高到低：`5000 / 2000 / 800 / 400 / 100`

## ⑦ 難度曲線與教學手法

### 世界 1-1 的四步教學（起跳前 ~10 秒內完成）[源＋推論]
1. **安全展示**：玩家出生於空曠地面，畫面右側有一隻緩慢的栗寶寶。什麼都不做會被撞到 → 學會「碰到會受傷」。
2. **誘導**：栗寶寶正下方偏右是 `?` 磚；不管玩家跳或不跳，蘑菇都會被牆與水管彈回玩家身上 → **保證玩家一定吃到蘑菇**（岩田聰在《岩田問》中特別點名這段設計「非常高明」）。[源]
3. **變奏**：第一個坑底部是實心的（掉下去不會死），讓玩家安全嘗試長跳；緊接著幾乎同形狀的第二個坑是真的會死。[源]
4. **結論**：水管高度遞增（2 → 3 → 4 格）＋ 食人花，把「跳躍高度控制」逼出來。

這正是 Kishōtenketsu（起承轉合）式關卡設計的原型；任天堂在《超級瑪利歐 3D 世界》由林田宏一明確把它作為關卡設計方法論說出來。[源]

### 全域難度曲線
| 世界 | 主要新增壓力 |
|---|---|
| 1 | 踩、跳、水管、蘑菇 |
| 2 | 水中關（新物理）、升降台 |
| 3 | 夜間 + 移動平台 + 錘子兄弟 |
| 4 | Lakitu + 刺龜（不可踩） |
| 5 | 高速平台 + 綜合 |
| 6 | 風 / 長距離跳躍 |
| 7 | 錘子兄弟密度 |
| 8 | 全要素綜合 + 長城堡迷宮 |

- **同關內的節奏**：緊張段（連續障礙）→ 緩衝段（空地 / 金幣）→ 更緊張段，約每 8–15 秒交替一次。[推論]
- **懲罰輕**：死亡只回到中途點，關卡短（30–90 秒），所以難度可以放很高。[推論]

## ⑧ 技術亮點

1. **單向捲動省去回捲成本**：畫面只能往右，程式只需維護「右側新出現的一欄」的 nametable 寫入，不必處理左側重建。這也是關卡資料能極度壓縮的前提。[推論]
2. **物件式關卡資料**：關卡以「物件 + 相對位移」列表描述（例如「向右 3 格放一個 4 格高水管」），而非逐格點陣，所以 32 KiB 才塞得下 32 關。[源：`ROM map` 的 area object data]
3. **狀態欄用固定的最上方 2 行**：SMB 的狀態列不捲動，靠 PPU 在畫面頂端保留非捲動區域（垂直捲動固定為 0 的處理），避免使用 mapper IRQ（NROM 也沒有）。[推論]
4. **調色盤複用**：地上 / 地下 / 水中 / 城堡共用同一組 CHR 磚，只換 palette 與背景色，達成「4 種世界觀、1 份圖形」。[源：CHR 僅 8 KiB]
5. **速度以 1/16 px、位置以 1/256 px 的定點數**儲存，讓 8-bit CPU 也能有平滑的加減速。[源]
6. **敵人上限**：同時最多 5 個敵人物件槽（另有專用槽給旗杆等），避免超過 8 sprite/scanline 造成閃爍。[推論]

## ⑨ 音樂音效特色

- 作曲：近藤浩治。原聲僅 **6 首背景曲**（地上、地下、水中、城堡、無敵、過關/結局）＋數段 jingle，全部塞在剩餘 ROM 內。[源]
- 地上曲採 **拉丁 / 加勒比切分節奏**，以脈衝波 1（旋律）+ 脈衝波 2（和聲）+ 三角波（貝斯）+ 噪音（鼓）四聲道分工，成為後世 NES 配樂的標準編制。[推論]
- 設計上「音樂隨玩法改變」：時間剩 100 秒時曲速加快（同一份資料改變播放速率），是最早的動態音樂之一。[源]
- 音效與動作一對一：小跳 / 大跳用不同音效（`Sfx_SmallJump` / `Sfx_BigJump`），讓玩家用耳朵確認自己的狀態。[源：反組譯]

## ⑩ 對原創遊戲的可借鑑清單（10 條）

1. **速度用定點數**：位置 1/256 px、速度 1/16 px 為單位；走路上限設 1.5 px/f、跑步 2.5 px/f，是經過 40 年驗證的舒適區間。
2. **跳躍用「兩段重力」實作可變高度**：上升中按住＝小重力（0.125 px/f²），放開＝大重力（0.4375 px/f²）。比例約 **1 : 3.5**。
3. **起跳初速隨水平速度分段**：至少做 2 段（慢 −4 px/f、快 −5 px/f），讓「跑跳」在手感上真的不同（4 格 vs 5 格）。
4. **加速要慢、煞車要快**：轉向時的加速度直接 ×2。這一條讓角色「有重量但不遲鈍」。
5. **空中加速設門檻**：空中只有在水平速度已達某值（如上限的 62%）時才允許繼續加速，否則鎖在走路上限——避免玩家用空中微調取代地面助跑。
6. **受傷無敵約 2.8 秒、道具無敵約 12 秒**：受傷無敵長到足以逃離擁擠場面，道具無敵長到足以衝過一整段關卡。
7. **敵人一隻一條規則**：不要給敵人第二種行為，改用「同外型不同顏色 = 不同規則」（綠龜會掉下平台 / 紅龜不會）來擴充。
8. **連鎖獎勵表**：踩敵連鎖 100→200→400→500→800→1000→2000→4000→5000→8000→1UP，最後一項給命而不是分數，玩家才會想追。
9. **第一關用「安全展示 → 誘導 → 變奏 → 結論」四段**：而且把第一個坑底部填實，讓玩家的第一次失敗不是死亡。
10. **魔王 = 一段程式 + 一張參數表**：以「攻擊組合表（是否吐火 / 是否跳 / 錘子頻率）× 關數」產生多個魔王，並同時提供「技巧解」與「路線解」兩種破法。
